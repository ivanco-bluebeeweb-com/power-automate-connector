# Power Automate Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Ops/IT-специалист в компании на экосистеме Microsoft 365, использующий Power Automate
для связывания Outlook/SharePoint/Teams/Dynamics и других MS-сервисов автоматизациями.

## 2. Момент истины после подключения
Сразу после `connect_power_automate` — список потоков (flows) с их статусом (включён/
выключен) и когда последний раз срабатывал — видно, что реально работает прямо сейчас.

## 3. Что пользователь видит
- Потоки (flows) целиком со всеми шагами и триггерами — `list_flows`, `get_flow`.
- Историю запусков потока с ошибками по шагам — `list_flow_runs`, `get_flow_run`.
- Подключения (connections к Outlook/SharePoint/Teams и т.д.) — `list_connections`.
- Среды (environments) организации — `list_environments`.
- Решения (solutions — пакеты потоков для переноса между средами) — `list_solutions`.
- Одобрения (approvals), ожидающие решения пользователя, — `list_approvals`.

## 4. Чем пользователь может управлять
- Включать/выключать поток — `enable_flow`, `disable_flow`.
- Запускать поток вручную (для потоков с ручным триггером) — `run_flow`.
- Отменять выполняющийся запуск — `cancel_flow_run`.
- Утверждать/отклонять approval-запрос — `respond_to_approval`.
- Экспортировать/импортировать поток между средами (dev → prod) — `export_flow`,
  `import_flow`.
- Делиться потоком с другим пользователем/командой — `share_flow`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'какие мои потоки сейчас выключены?'. Она находит через
`list_flows`, а я прошу включить нужный — `enable_flow` делает это без захода в
Power Automate портал."

## 6. Что делает это "заточенным под него"
`list_environments`/`list_solutions` работают с РЕАЛЬНОЙ структурой сред именно этой
организации (dev/test/prod) — критично для компаний с формальным процессом релиза.
